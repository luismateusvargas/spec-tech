# Orchestrate simple code

1. Find the project root, active instructions, existing specs, entry files, runtime or target sites, dependencies, and available checks. Consult Caipira when available; verify current file facts in the project. Inspect permissions, external requests, and stored data if relevant.
2. Use the simple section of the [questionnaire](../sdd-shared/templates/orchestrator.questionnaire.md) with the user. Reuse confirmed decisions from existing plans or memory, prefill verified facts, and ask only for unresolved purpose or rules. Omit optional fields that do not apply. Leave an unanswered required decision explicit rather than guessing. Fill the shared [simple project template](../sdd-shared/templates/project.simple.template.md). Preserve existing rules and specs. Keep enduring rules in its constitution section; if a separate constitution already exists, link it instead.
3. Check current primary documentation only where version, platform, permission, or security behavior affects a decision. Record the source and access date. Mark unknown behavior rather than inventing it.
4. Verify paths and the stated run or test procedure. Report the updated spec path and unresolved questions. Add deeper security or compatibility requirements when the actual risk warrants them.
